# Splash feature

## Purpose
First screen shown on launch. Displays the branded splash background with the app logo centered over it for 2 seconds, then routes to the login screen. No session resolution yet — intentionally minimal.

## Architecture
Layered under `features/splash/presentation`:
- `cubit/splash_state.dart` — `SplashState`, a **`@freezed` empty-payload state** (`const factory SplashState() = _SplashState;` — no fields, the splash has no visual state of its own).
- `cubit/splash_cubit.dart` — `@injectable` `SplashCubit`. Injects `GoRouter` directly (no `BuildContext`). Owns a single 2-second `Timer` (started via `start()`) that, once it fires, calls `_goRouter.goNamed(AppRouteNames.login)`, guarded by `if (isClosed) return;`. The timer is cancelled in `close()`.
- `screens/splash_screen.dart` — `SplashScreen`, a `StatefulWidget` that calls `context.read<SplashCubit>().start()` in `initState` and renders an `AppScaffold` (`safeArea: false`, background fills the whole screen) stacking `Assets.images.backgrounds.splashBackground.image(fit: BoxFit.cover)` behind `Assets.images.logo.image(...)` — both generated by `flutter_gen_runner` (`lib/gen/assets.gen.dart`), no hardcoded asset path strings.

## Native splash (OS-level, pre-Flutter-frame)
Separate from the in-Flutter `SplashScreen` widget above: the `flutter_native_splash:` block in `pubspec.yaml` (color `#FFFFFF`, `background_image: assets/images/logo.png`, `fullscreen: true`, `android_gravity`/`ios_content_mode: center`, plus an `android_12:` sub-block) configures the OS splash shown before the Flutter engine renders its first frame.

**Action required (cannot be run from this sandbox — no Flutter/Dart SDK, network egress blocked):**
```
dart run flutter_native_splash:create
```
Run this locally after any change to the `flutter_native_splash:` config or to `assets/images/logo.png`, then rebuild the app.

## State management
`Cubit` + Freezed empty-state — used only to sequence navigation, not to hold data.

## Dependency injection
`SplashCubit` is `@injectable` (not `@lazySingleton` — a fresh instance per launch is fine since splash only runs once per process lifetime).

## Routing
Registered at `AppRoutes.splash` (`/`) as the router's `initialLocation`. Flow: `splash (/)` → after 2s → `login (/login)`.

## To make it real
Resolve the session inside `SplashCubit.start()` (e.g. check `SecureStorageUtil` for a saved token) before deciding whether to route to `login` or straight to `home`.
