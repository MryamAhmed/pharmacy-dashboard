# Home module

## Purpose
Landing experience shown after a successful login. A bottom-navigation shell hosting four tabs: **Home**, **Pharmacy Management**, **Rate**, and **User Management**. Home and Rate have real (if dummy) data wiring; Pharmacy Management and User Management are still placeholder screens — this module establishes the Clean Architecture scaffolding and tab-navigation shell so each tab's real feature can be built out independently.

## Architecture
Module-level `data`/`domain` layers (shared by the module, not per-tab):
- `domain/entities/home_summary_entity.dart` — `HomeSummaryEntity` (pure Dart), currently just a `greeting` string.
- `domain/repositories/home_repository.dart` — `HomeRepository` abstract contract.
- `domain/usecases/get_home_summary_usecase.dart` — `@injectable` `GetHomeSummaryUseCase`, single `call()`.
- `data/models/home_summary_response.dart` — `HomeSummaryResponse` (`fromJson` / `toDomain`).
- `data/datasources/home_remote_data_source.dart` — `HomeRemoteDataSource` (abstract) / `HomeRemoteDataSourceImpl`, annotated `@LazySingleton(as: HomeRemoteDataSource)`. **Dummy for now**: returns a static greeting after a simulated delay instead of calling a real endpoint. Swap the body for a real `callApi(...)` call against `DioClientService` when the backend exists — the `Either<AppError, HomeSummaryResponse>` return shape already matches every other data source in the app.
- `data/repositories/home_repository_impl.dart` — `HomeRepositoryImpl`, annotated `@LazySingleton(as: HomeRepository)`, maps failures to `AppError`.

Rate tab's own `data`/`domain` layers (same shape as Home's, one layer set per tab once a tab needs real state):
- `domain/entities/rate_entity.dart` — `RateEntity` (pure Dart): `id`, `pharmacyName`, `userName`, `dateTime`, `status` (`RateStatus`), `reviewText`, `rate` (`int`).
- `core/enums/rate_status.dart` — `RateStatus` enum (`approve` / `pending` / `reject`), lives in `lib/core/enums/` (the app's shared enum location, not under the feature's `domain/entities/`) with a `RateStatus.fromValue(String?)` parser defaulting to `pending` on an unrecognized value.
- `domain/repositories/rate_repository.dart` — `RateRepository` abstract contract, `getRates()`.
- `domain/usecases/get_rates_usecase.dart` — `@injectable` `GetRatesUseCase`, single `call()`.
- `data/models/rate_response.dart` — `RateResponse` (`fromJson` reading snake_case keys `pharmacy_name`/`user_name`/`datetime`/`status`/`review_text`/`rate` / `toDomain`).
- `data/datasources/rate_remote_data_source.dart` — `RateRemoteDataSource` (abstract) / `RateRemoteDataSourceImpl`, annotated `@LazySingleton(as: RateRemoteDataSource)`. **Dummy for now**: after a simulated `Duration(seconds: 1)` delay, returns 6 hardcoded `RateResponse`s — the original 3 (one per `RateStatus` value) plus 4 more `pending` reviews spanning `rate` 2-4, so every `RateRatingFilter` bucket has at least one entry to exercise the tabs/list against. Swap the body for a real `callApiList(...)` call against `DioClientService` when the backend exists — the `Either<Failure, List<RateResponse>>` return shape already matches every other data source in the app.
- `data/repositories/rate_repository_impl.dart` — `RateRepositoryImpl`, annotated `@LazySingleton(as: RateRepository)`, maps failures to `AppError` and each `RateResponse` to a `RateEntity`.
- `core/enums/rate_rating_filter.dart` — `RateRatingFilter` enum (`all` / `five` / `four` / `three` / `oneOrTwo`), also in `lib/core/enums/` alongside `RateStatus`. `matches(int rate)` tests whether a review's 1-5 `rate` falls in the bucket (`oneOrTwo` covers both 1★ and 2★); `label(String localizedAll)` returns the short display string shown before the count on each tab chip — only `all` is a translatable word (`localizedAll`, passed in as `context.l10n.rateFilterAll` by the caller), the star-count labels (`'5★'`, `'1-2★'`, etc.) are numeric symbols and stay hardcoded. This enum stays Flutter/l10n-agnostic on purpose (`core/enums/` has no Flutter imports) — resolving the actual localized string is the caller's job.

Presentation, one folder per tab:
- `presentation/home_shell/screens/home_shell_screen.dart` — `HomeShellScreen`, a `StatefulWidget` holding the selected tab index and an `IndexedStack` of the four tab widgets (so switching tabs preserves each tab's state). Does **not** provide any Cubit itself — `HomeTabCubit` and `RateCubit` are both provided once, above `HomeShellScreen`, by the `home` `GoRoute`'s `MultiBlocProvider` (see Routing below); `HomeTabScreen`'s and `RateScreen`'s `BlocBuilder`s simply resolve them from that ancestor context.
- `presentation/home_shell/widgets/home_bottom_nav_bar.dart` — `HomeBottomNavBar`, the `BottomNavigationBar` with four items. Labels come from `context.l10n.navHome/navPharmacy/navRate/navUsers` (short, so all four fit on one line at narrow widths); each tab's on-screen title is the longer form (`homeTitle`, `pharmacyManagementTitle`, `rateTitle`, `userManagementTitle`).
- `presentation/home_tab/` — the only tab with real (if dummy) data wiring:
  - `cubit/home_tab_state.dart` — **`@freezed`** state: `isLoading`, `greeting`, and the raw `AppError? error` (not a pre-resolved string — resolving display text is left to the screen via `AppErrorX.resolveMessage(context.l10n)`, keeping the Cubit free of `BuildContext`).
  - `cubit/home_tab_cubit.dart` — `@injectable` `HomeTabCubit`, calls `GetHomeSummaryUseCase` on creation, folds the `Either` result with `.fold()`, guarded by `if (isClosed) return;`.
  - `screens/home_tab_screen.dart` — `HomeTabScreen`, app-bar title is `context.l10n.homeGreeting(AppConstants.homePlaceholderUserName)` (localized template, dummy name placeholder pending real auth — mirrors the login screen's `loginWelcomeTitle`/`loginPlaceholderUserName` pattern). Body renders `state.error?.resolveMessage(context.l10n) ?? context.l10n.comingSoon` via `BlocBuilder`.
  - `widgets/home_dashboard_items_widget.dart` — `HomeDashboardItemsWidget`, 4 stat cards. Only the **subtitles** are localized (`context.l10n.homeDashboardUsersSubtitle/ActiveJobsSubtitle/PharmaciesSubtitle/ApplicationsSubtitle`); the numeric `title` values (`'1,248'`, `'342'`, `'89'`, `'4,102'`) are dummy data, left hardcoded.
  - `widgets/quick_actions_widget.dart` — `QuickActionsWidget`, section title + 3 action pills, **fully localized** (`quickActionsTitle`, `quickActionApproveRating`, `quickActionVerifyUsers`, `quickActionVerifyPharmacies`) — no dummy data in this widget.
  - `widgets/recent_activity_widget.dart` — `RecentActivityWidget`, only the section **title** is localized (`recentActivityTitle`); the two `RecentActivityItemWidget` entries (name, duration, icon) are dummy data, left hardcoded.
- `presentation/rate/cubit/rate_state.dart` — **`@freezed`** state: `isLoading` (default `true`), `rates` (`List<RateEntity>`, default `[]`), `selectedFilter` (`RateRatingFilter`, default `all`), and the raw `AppError? error` (not a pre-resolved string, same pattern as `HomeTabState`). Uses freezed's `const RateState._();` private-constructor pattern to add computed members alongside the generated `factory`:
    - `pendingRates` — `rates` narrowed to `status == RateStatus.pending` (what "reviews waiting for approval" and every tab count are actually counted from — approved/rejected reviews don't appear on this screen).
    - `filteredRates` — `pendingRates` further narrowed by `selectedFilter` (not yet consumed by the screen — no list UI renders the reviews themselves yet, only the summary text + tab row).
    - `countFor(RateRatingFilter filter)` — count of `pendingRates` matching `filter`, used for each tab chip's `(N)` suffix.
  - `presentation/rate/cubit/rate_cubit.dart` — `@injectable` `RateCubit(GetRatesUseCase, GoRouter)`, calls `GetRatesUseCase` on creation (so the tab's dummy list loads — after the data source's simulated 1s delay — as soon as the cubit is built, which happens once when the `home` route is entered), folds the `Either` result with `.fold()`, guarded by `if (isClosed) return;`. `selectFilter(RateRatingFilter)` just updates `selectedFilter` on the already-loaded state — it never refetches. `openRateDetails(RateEntity rate)` navigates to `AppRouteNames.rateDetails` via the injected `GoRouter` (`extra: rate`) — navigation is owned by the Cubit, not the widget, matching `LoginCubit`'s pattern.
  - `screens/rate_screen.dart` — `RateScreen`, `BlocBuilder<RateCubit, RateState>` showing `AppLoadingWidget` while `state.isLoading`, otherwise `RateListWidget(state: state)`. App-bar title is `context.l10n.ratePendingTitle`.
  - `presentation/rate/widgets/rate_list_widget.dart` — `RateListWidget`, owns the whole loaded body: the pending-count summary (`context.l10n.rateReviewsWaitingForApproval(state.pendingRates.length)`, key `TestKeys.numberOfPending`), `RateTabsWidget`, and an `Expanded(ListView.separated(...))` over `state.filteredRates` — or `context.l10n.rateEmptyState` (key `TestKeys.rateEmptyState`) when the current filter matches nothing.
  - `presentation/rate/widgets/rate_tabs_widget.dart` — `RateTabsWidget`, Rate-specific adapter around the shared `AppFilterTabsWidget`: maps every `RateRatingFilter` value into an `AppFilterTab` (localized label + `state.countFor(filter)`, keyed `'${TestKeys.rateFilterTab}_${filter.name}'`), `selectedValue` is `state.selectedFilter`, `onSelected` calls `context.read<RateCubit>().selectFilter`.
  - Shared filter tabs (used by Rate and any other screen that needs a compact chip row):
    - `shared/presentation/widgets/app_filter_tab.dart` — `AppFilterTab<T>`, config only (not a widget): `value`, localized `title`, optional `count`, and `itemKey`. Omit `count` for label-only chips; pass any list length (Rate uses 5, another screen can pass 4).
    - `shared/presentation/widgets/app_filter_tab_chip_widget.dart` — `AppFilterTabChipWidget`, a small tappable filter chip (`GestureDetector` wrapping a `Container`). Deliberately **not** built on the shared `AppButtonWidget` — that widget bakes in a fixed 16sp label and a full-width/default-height layout, neither of which fits this compact 30px-tall, 10sp-text segmented chip. Dimensions live in `AppFilterTabsDimens`.
    - `shared/presentation/widgets/app_filter_tabs_widget.dart` — `AppFilterTabsWidget<T>`, equal-width `Row` of chips with `AppSpace.s8` gaps. Appends `(count)` to the title only when `AppFilterTab.count` is set.
  - `presentation/rate/widgets/rate_card_widget.dart` — `RateCardWidget(rate: RateEntity)`, one review card: `TextAvatarWidget` seeded with `pharmacyName[0].toUpperCase()`, pharmacy name + `context.l10n.rateForUser(userName)`, stars as `List.filled(rate.rate, '★').join(' ')` (count driven by the model, not hardcoded), a relative-time label from a private top-level `_relativeTime(DateTime)` helper (`Xd/Xh/Xm ago` / `'just now'`, computed from `rate.dateTime`), the review text, and an `AppButtonWidget` reading `context.l10n.rateApproveButton` with an **empty `onPressed: () {}`** (approve/reject logic isn't wired yet — intentionally left as a no-op). The whole card is wrapped in a `GestureDetector` that calls `context.read<RateCubit>().openRateDetails(rate)`.
  - `presentation/rate/widgets/text_avatar_widget.dart` — `TextAvatarWidget`, a circular initial-letter avatar (`title` is whatever single-letter string the caller passes in — callers, not this widget, decide it's the first letter of a name).
- `presentation/pharmacy_management/screens/pharmacy_management_screen.dart`, `presentation/user_management/screens/user_management_screen.dart` — pure UI stubs rendering the shared `AppComingSoonView` widget with a tab-specific icon and `context.l10n.<tab>Title` / `context.l10n.comingSoon`. No cubits yet — add one per tab as each becomes real.

## State management
`Cubit` + **Freezed** state throughout (`HomeTabState`, `RateState`; `PharmacyManagementScreen`/`UserManagementScreen` have no state yet since they're static placeholders).

## Dependency injection
`HomeRemoteDataSourceImpl`, `HomeRepositoryImpl`, `GetHomeSummaryUseCase`, `HomeTabCubit`, `RateRemoteDataSourceImpl`, `RateRepositoryImpl`, `GetRatesUseCase`, and `RateCubit` are all registered via Injectable annotations (`@LazySingleton(as: Interface)` / `@injectable`) — nothing in this module is manually registered in `core/di/di.dart`. Wiring is generated into `di.config.dart` by `build_runner` (gitignored — regenerate locally with `dart run build_runner build --delete-conflicting-outputs`).

## Routing
Registered at `AppRoutes.home` (`/home`) as `HomeShellScreen`, wrapped in a `MultiBlocProvider` (in `app_router.dart`) that provides both `HomeTabCubit` and `RateCubit` for the whole shell — this is where each tab's Cubit is constructed, not inside `HomeShellScreen` or per-tab. Navigated to by `LoginCubit.submit()` via `GoRouterNavigationX.clearStackAndGo`. Tab switches are in-memory (`setState` on the shell) — not represented in the URL. Upgrade to `StatefulShellRoute.indexedStack` if deep-linking to a specific tab is needed later.

Tapping a `RateCardWidget` leaves this module entirely: `RateCubit.openRateDetails(rate)` calls `GoRouter.pushNamed(AppRouteNames.rateDetails, extra: rate)`, a separate top-level route (`/rate-details`) that renders `RateDetailsScreen` from the standalone `rate_details` feature module — see `lib/features/rate_details/docs/rate_details.md`.

## Localization
All Home strings live in `app_en.arb`/`app_ar.arb`: `homeTitle`, `pharmacyManagementTitle`, `rateTitle`, `userManagementTitle`, `navHome`, `navPharmacy`, `navRate`, `navUsers`, `comingSoon`, `searchHint`, plus the home-tab dashboard keys added for the tab widgets — `homeGreeting` (`{name}` placeholder), `recentActivityTitle`, `quickActionsTitle`, `quickActionApproveRating`, `quickActionVerifyUsers`, `quickActionVerifyPharmacies`, `homeDashboardUsersSubtitle`, `homeDashboardActiveJobsSubtitle`, `homeDashboardPharmaciesSubtitle`, `homeDashboardApplicationsSubtitle`. Per-widget, only some of these are localized today — see the widget notes above for which strings are copy (localized) vs. dummy data (hardcoded, intentionally not translated). `AppConstants.homePlaceholderUserName` (`'Aya'`) is the stand-in signed-in-user name for `homeGreeting`, same pattern as `AppConstants.loginPlaceholderUserName` on the login screen.

Rate tab strings: `ratePendingTitle` (app-bar title — distinct from `rateTitle`, the bottom-nav tab label), `rateReviewsWaitingForApproval` (`{count}` placeholder), `rateForUser` (`{name}` placeholder), `rateApproveButton`, `rateFilterAll` (the only translatable tab label — star-count labels are numeric symbols), `rateEmptyState`. The relative-time label on each card (`_relativeTime()` in `rate_card_widget.dart`) and the star glyphs themselves are **not** localized — they're symbol/number based, not language text.
